# CYD Radar (ESP32-2432S028 + SG90 + HC-SR04) — VS Code + PlatformIO 版

<img width="1008" height="631" alt="IMG_2608" src="https://github.com/user-attachments/assets/e3cda564-ddc1-4c96-b6c6-5d76b8b8f4ea" />


SG90 で HC-SR04 を 15°〜165° に振りながら測距し、CYD の画面に
レーダー風 (半円・同心円・掃引線・赤い検出点) で表示するプロジェクトです。
上部に現在の角度と距離も数字で出ます。シリアル (115200bps) にも
`角度,距離cm` を出すので、画面なしでも動作確認できます。

> 型番について: 一般に CYD の 2.8インチ機は **ESP32-2432S028**
> (240×320) です。「2428S028」と書かれていたので、この機種として
> 作っています。基板裏の金色の印字で確認してください。

## プロジェクト構成

```
cyd-radar/
├─ platformio.ini     ← ボード・ライブラリ・TFT_eSPI 設定は全部ここ
├─ src/
│  └─ main.cpp        ← 本体コード
└─ .vscode/
   └─ extensions.json ← PlatformIO 拡張の推奨設定
```

TFT_eSPI の設定は、Arduino IDE 流の `User_Setup.h` 書き換えではなく、
`platformio.ini` の `build_flags` で渡しています。
ライブラリを更新しても設定が消えません。

## 開き方・書き込み方 (VS Code + PlatformIO)

1. VS Code に拡張機能 **PlatformIO IDE** を入れる
   (このフォルダを開くと `.vscode/extensions.json` により推奨表示されます)
2. VS Code でこの `cyd-radar` フォルダを開く
   (「ファイル → フォルダーを開く」、またはターミナルで `code .`)
3. 初回はライブラリ (TFT_eSPI / ESP32Servo) とツールチェーンが
   自動ダウンロードされるので、少し待ちます
4. CYD を USB でつなぎ、下部バーの **→ (Upload)** を押すと
   ビルドと書き込みが走ります
5. 下部バーの **コンセント型アイコン (Serial Monitor)** で
   `角度,距離cm` のログが見えます

コマンドライン派の場合は:

```bash
pio run -e cyd -t upload   # ビルド + 書き込み
pio device monitor         # シリアルモニタ (115200bps)
```

### 基板リビジョンが違う場合 (デュアルUSB版)

micro-USB + USB-C の両方がある版 (CYD2USB) は画面コントローラが
ST7789 系のことがあります。画面が出ない・色がおかしい場合は、
VS Code 下部バーの環境名をクリックして **`cyd2usb`** に切り替えて
書き込み直してください (`platformio.ini` に環境を用意してあります)。
色の反転が残る場合は `platformio.ini` の cyd2usb 環境にある
`TFT_INVERSION_ON` の行のコメントを参照してください。

## なぜこのピン割り当てなのか

CYD はディスプレイ・タッチ・SD・LED 等でほとんどの GPIO を使っており、
外部に使えるのは実質 **GPIO 22 / 27 / 35 の3本だけ** です
(CN1 と P3 コネクタに出ています)。必要な信号もちょうど3本なので、
過不足なく収まります。

| 信号 | GPIO | コネクタ | 備考 |
|---|---|---|---|
| SG90 信号 (橙) | 27 | CN1 | PWM 出力 |
| HC-SR04 TRIG | 22 | CN1 / P3 | 出力 |
| HC-SR04 ECHO | 35 | P3 | **入力専用**ピンなので受信専用の ECHO に最適 |

GPIO21 (P3 に出ている) はバックライト用なので使いません。

コネクタは 1.25mm ピッチ (いわゆる JST 1.25 / PicoBlade 系) です。
ピン順は基板のシルクで必ず確認してください。

## 配線

### HC-SR04
- VCC → 外部 5V
- GND → 共通 GND
- TRIG → GPIO22
- ECHO → **分圧してから** GPIO35
  - ECHO は 5V 信号です。ESP32 に直接入れるとピンを壊す恐れがあります。
  - ECHO ─ 1kΩ ─┬─ GPIO35
                └─ 2kΩ ─ GND
  - (5V × 2/3 ≒ 3.3V になります)

### HC-SR04P (3.3v版）
上記と同じピン接続で、 ECHO は 3.3V なので、抵抗による分圧は不要です。

### SG90
- 信号 (橙) → GPIO27
- 電源 (赤) → 外部 5V
- GND (茶) → 共通 GND

### 電源 (重要)
- SG90 は動作時に数百 mA (止まると ~650mA) 流れるため、
  CYD の USB 電源と共用すると電圧降下で ESP32 がリセットしたり
  画面がちらつくことがあります。
- **別の 5V/2A 電源** (USB 充電器 + ブレッドボード電源など) から
  SG90 と HC-SR04 に給電し、**GND だけ CYD と共通** にしてください。
- SG90 の電源近くに 470〜1000µF の電解コンデンサを入れると安定します。
- CYD の 3.3V ピンからは絶対に給電しないでください。

## 調整

`src/main.cpp` 冒頭の定数で調整できます。

- `MAX_RANGE_CM` (初期値 150): 表示レンジ。屋内なら 100〜150 が見やすい
- `ANGLE_STEP` (初期値 3): 小さいほど細かいが掃引が遅くなる
  (40ms の待ち + 測距で、片道およそ 2〜3 秒)
- `INVERT_DIRECTION` : センサーの実物の向きと画面の左右が逆なら 1 にする
- 左右 15° ずつ余白を取っているのは、SG90 の端付近の精度と
  センサー (測定角 約15°) の広がりを避けるためです

## 既知の割り切り

- 掃引線を消すときにリング・放射線も一緒に薄れます。
  掃引が端に着くたびに静止画を描き直しています。
  気になるようならスプライト描画版に作り替えます。
- HC-SR04 の測距は `pulseIn` のブロッキング測定です (最大 30ms)。
  この用途では問題になりません。
- 実機での動作確認前に、まずシリアル出力で「角度ごとに距離が変わるか」だけ確認すると切り分けが楽です。
